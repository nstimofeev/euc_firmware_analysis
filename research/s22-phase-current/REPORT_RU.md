# S22 2.41: фазные токи измеряются через ADC2

**Да: основная плата измеряет фазные токи, независимо от измерительного тракта батарейного тока.** В проверенной прошивке S22 2.41 используются три аналоговых канала ADC2, соответствующие фазам A/B/C. За один цикл выполняются два последовательных преобразования. Выбираемая пара зависит от сектора ШИМ; недостающий компонент восстанавливается из соотношения суммы фазных токов. Далее измерения переходят в α/β и d/q и используются регулятором мотора.

Это уточняет прежние отчёты: наличие диагностических имён `IA`, `IB`, `IQCurrent` само по себе не было доказательством измерения. Теперь прослежены реальное чтение ADC-регистров, выбор пары, калибровка нулей и путь до токовых переменных.

## 1. Какие измерения делает ADC

| Сектор ШИМ | Измеряемая пара | ADC2, первая/вторая конверсия | Восстанавливается при формировании IA/IB |
|---|---|---|---|
| 1, 6 | B + C | канал 1 / канал 2 | A = −(B + C) |
| 2, 3 | A + C | канал 3 / канал 2 | B = −(A + C) |
| 4, 5 | A + B | канал 3 / канал 1 | IA/IB берутся непосредственно из этих двух измерений; C для последующих преобразований не нужен |

Три номера каналов берутся из таблицы `0x080270ac`: u32 `3, 1, 2`. Код `0x0800bb24–0x0800bb3e` сдвигает их на 15 бит и сохраняет в RAM `0x200034d8`, `0x200034dc`, `0x200034e0`.

Функция модуляции `0x080101b4` вычисляет сектор RAM `0x20000378` и выбирает два канала через RAM `0x20000370/0x20000374`. Она также задаёт момент выборки регистром TIM1 CCR4 (`0x40012c40`).

`0x0800c944` программирует injected sequence ADC2:

```text
ADC2_JSQR = RAM[0x20000374] + (RAM[0x20000370] >> 5) + 0x100000
```

В итоге JSQR равен `0x110400` (B/C), `0x110c00` (A/C) или `0x108c00` (A/B). Биты JL=1 означают две конверсии; два канала находятся в JSQ3/JSQ4. Чтение результатов идёт из **ADC2 JDR1 `0x4001283c` и JDR2 `0x40012840`** в `0x0800c560`.

Карта регистров и трактовка битов сверены с первичным справочником [ST RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf), разделы ADC injected sequence/data registers, CR2 и TIM1. Это STM32F1-совместимая карта, не доказательство маркировки конкретного MCU.

Инициализация `0x0800c978` задаёт две injected-конверсии и CR2=`0x9000`: источник TIM1 CC4, external injected trigger разрешён. ADC IRQ `0x0800863c` при флаге JEOC запрещает повторный trigger и в состояниях 4/5 вызывает моторный обработчик `0x0800b91c`. TIM1 update IRQ `0x08010b84` вновь программирует последовательность и разрешает trigger. Следовательно, выборки привязаны к ШИМ, а не к медленному опросу BMS. Частота и точность реальной электроники здесь не измерялись.

## 2. Ноль, знак и восстановление

`0x0800c6b0` калибрует три отдельных нуля. Для A/B суммируются 64 отсчёта ×2, затем деление на 64; C калибруется отдельными 64 отсчётами ×2 после переключения второго канала. Нули сохраняются в RAM `0x200034e4/e8/ec`.

Для сырого значения **регистра результата** `R` измеренный компонент имеет вид:

```text
I_phase_raw = sat16(Z_phase − 2 × R)
sat16: ограничение от −32768 до +32767
```

Это внутренние единицы; формула не задаёт амперы. Восстановление также имеет ограничение sat16. Конкретные выражения оригинального кода:

```text
секторы 1/6: IB = sat16(ZB − 2×JDR1)
             IA = sat16(2×JDR2 − ZC − IB)
секторы 2/3: IA = sat16(ZA − 2×JDR1)
             IB = sat16(2×JDR2 − ZC − IA)
секторы 4/5: IA = sat16(ZA − 2×JDR1)
             IB = sat16(ZB − 2×JDR2)
```

Из-за последовательного насыщения при выходе за пределы диапазона нельзя считать результат математически точным восстановлением трёх реальных токов. В обычном ненасыщенном диапазоне эти выражения соответствуют `IA+IB+IC=0`.

## 3. Путь в регулятор

| Звено | Код | RAM |
|---|---|---|
| ADC2 → два фазных компонента | `0x0800c560` | возвращает пару в буфер вызывающей функции |
| Сохранение IA/IB | `0x0800b926–0x0800b92c` | `IA=0x20003488`, `IB=0x2000348c` |
| Преобразование Clarke | `0x0800b6d4` | `Ialfa=0x20003498`, `Ibeta=0x2000349c` |
| Преобразование с электрическим углом | `0x0800b708`, оригинальный тригонометрический помощник `0x0800a72c` | результат d/q в буфере; коэффициенты RAM `0x2000038c/390` |
| Запись IQCurrent/IDCurrent | `0x0800b998–0x0800ba1a` | `IQCurrent=0x200034a0`, `IDCurrent=0x200034a4`; изменение ограничено ±3000 за вызов |

Преобразование Clarke в этом коде:

```text
Ialpha = IA
Ibeta = trunc(−(IA×0x49e6 + IB×0x93cc) / 32767)
```

Преобразование d/q после получения коэффициентов `C/S` из электрического угла:

```text
Iq_before_limit = trunc((Ialpha×C − Ibeta×S) / 32767)
Id_before_limit = trunc((Ibeta×C + Ialpha×S) / 32767)
```

Имена IQ/ID установлены не предположением о порядке результатов, а конкретными последующими записями и диагностическими дескрипторами. Псевдокод также показывает дальнейшее использование `IDCurrent` в регуляторе `0x0800b81c` и `IQCurrent` в сглаживании/ограничении; полный регулятор здесь не эмулировался.

**`Iq/Id` вычисляются из измеренных фазных токов и угла.** Расчёт координат не делает исходные фазные токи оценкой по PWM или батарейному току. `BusCurrent` расположен отдельно (`0x200032c4`); в проверенной IRQ-цепочке его изменение не требуется.

## 4. Ограниченная проверка оригинального кода

Входы: SHA-256 приложения `99491754f5478caf5d97a5fa31c0a17bc7be55f0c14ee3f87058b55916fe9509`, начальной RAM `aaa8b3bc063cf1c0f7e200d01b6c1c204161abd764ad9b7dbce6048866a7ffea`.

```sh
python research/s22-phase-current/trace_phase_current.py
```

Проверены:

- инициализация injected ADC2, все шесть секторов и три переключаемые пары каналов;
- исходный TIM1 update IRQ: программирование последовательности и разрешение trigger;
- 64 отсчёта для каждого из трёх нулей;
- 30 комбинаций сектора, знака, разных нулей и насыщения: код реально читает JDR1/JDR2;
- 12 проходов ADC IRQ → IA/IB → Clarke: шесть секторов × состояния 4/5;
- четыре угла для исходного преобразования d/q с исполнением тригонометрического помощника;
- две проверки записи IQ/ID с ограничением изменения ±3000.

Пример управляемых входов: сектор 4, ZA=ZB=32768, JDR1=16300, JDR2=16500 → IA=168, IB=−232 → Ialpha=168, Ibeta=170. `BusCurrent=12345` остаётся прежним. Это значения офлайн-теста, не физические амперы.

Результат — `evidence.json`; `current-path-v241.asm` содержит реально исполненные начала инструкций в выбранных областях. Все помощники прошивки исполняются без заглушек. ADC/TIM/MMIO представлены памятью, настоящие конверсии и двигатель не моделируются. Значения аппаратных регистров задаются как управляемые входы; сравнение с формулами выполняется отдельно от оригинальных инструкций.

Точный физический датчик (шунт/усилитель/Hall), номиналы, амперы на единицу, задержка/точность измерения и перенос результата на другие аппаратные ревизии ещё не установлены. Прошивка доказывает три используемых аналоговых канала, но не позволяет без схемы однозначно посчитать физические датчики и назвать их тип.
