# Правила выполнения волны анализа 2026-09-29

Цель: завершить проверяемый пакет анализа S22 и 16X для сообщества. Без изменения прошивок, подключения к колесу и физических действий. Эта первая волна закрывает конкретные пробелы, не обещает восстановить весь исходный проект.

## Организация
- Работа только в назначенном поддереве. Чтение всего репозитория разрешено. Общие отчёты, manifests, исходные бинарники и чужие скрипты не менять.
- Git add/commit/push, ветки и публикацию выполняет только основной агент. Не запускать старые генераторы, пишущие в чужие директории: перенести вывод или импортировать функции в собственный скрипт.
- Репозиторий `/workspace/scratch/b7efaac7930c/euc_firmware_analysis`; Python `../s22-analysis-venv/bin/python`.
- Работать на имеющихся артефактах. Внешние сведения искать только если нужны для конкретного пробела; первичные источники, URL и дата. Не выполнять широкое сканирование серверов.
- Автоматический C — псевдокод. Существенные выводы подкреплять адресами, байтами, потоком данных и при возможности ограниченной эмуляцией оригинальных инструкций.
- Модель формулы на Python не называть эмуляцией прошивки; совпадение нормализованного кода не называть доказательством одинакового поведения.
- Отсутствие найденной проверки не доказывает отсутствия проверки. AES/CRC не доказывают принятия патча загрузчиком. Одинаковые строки/параметры не доказывают совместимости плат.

## Выход каждого задания
1. `REPORT_RU.md`: выводы, конкретные адреса/версии, ограничения, что изменилось относительно прежних отчётов.
2. Структурированное JSON-доказательство и воспроизводящий скрипт, если применяется извлечение/эмуляция. Входные SHA-256 и команда запуска.
3. `STATUS.json`: выполнено, открытые вопросы, команды проверки и результат, следующий конкретный шаг. Не подставлять уверенные ответы вместо неизвестных.
4. Сообщение основному агенту с 2–5 важными находками, путями, временем/зависимостями. Если задача слишком велика, закончить воспроизводимый первый срез и описать остаток.

Основной агент проверяет критические выводы, объединяет материалы, обновляет хеши и публикует. Проверенные результаты и нерешённые вопросы остаются раздельны.
