# S22 BMS 2.10: батарейный ток измеряется

**В найденной прошивке `KSS22BA-2202-2.10` ток батареи происходит от собственного ADC BMS.** Это измерение с цифровым масштабированием, калибровочными коэффициентами, порогами и фильтрацией. Цепь прослежена до поля тока ответа `0x42` и проверена исполнением оригинальных STM8-инструкций, включая арифметические помощники прошивки.

## Образ и происхождение

Из публичного [дампа S22](https://github.com/jeremy-prater/ks-s22-mods/blob/9258eac039304991a815b8880c4dddca7a4e983c/firmware/capture.bin) извлечён образ обновления BMS, сохранённый в области подготовки обновления основной платы. Это отдельный исполняемый STM8-образ, а не ARM-код основной платы.

| Проверка | Результат |
|---|---|
| Дамп | 524 288 байт, SHA-256 `e1ad38200189fd445cf9cf805206ed853398124b2ffa2f5326040269d7fc3552` |
| Заголовок в дампе | `0x29000`: `fb 13 ff ff 1a e8 ff ff` |
| Извлечение | от `0x29008`, 5115 записей × 12 байт = 61 380 байт |
| Проверка целостности | CRC-16/CCITT, init=0, `0xe81a`; совпадает с заголовком |
| SHA-256 образа | `2003d5236b08f7a8dc51585ef34fb60eb7ad796f0716a6c1530c61cfcd09f843` |
| Архитектура и размещение | STM8; база `0x8b00`, reset vector → `0x17846`, конец образа `0x17ac4` |
| Собственное имя BMS | строка `KSS22BA-2202-2.10` по адресу `0x90c2` |
| Серийный идентификатор в образе | `KSC02A30222408***`, шаблон, не серийник конкретной батареи |

База установлена согласованностью векторов, адресов кода и ссылок на строки. Названия ADC-регистров соответствуют карте STM8L в [ST RM0031](https://www.st.com/resource/en/reference_manual/rm0031-stm8l050j3-stm8l051f3-stm8l052c6-stm8l052r8-mcus-and-stm8l151l152-stm8l162-stm8al31-stm8al3l-lines-stmicroelectronics.pdf). Точная модель MCU и физический датчик тока этим анализом не установлены. Дамп доказывает наличие подготовленного образа 2.10, но не версию, реально работавшую в батарее владельца дампа.

## От ADC к ответу BMS

| Звено | Адрес и действие |
|---|---|
| Прерывание ADC | `0x16f30`; после проверки флагов вызывается `0x15072` из `0x16f62` |
| Чтение результата ADC | `0x15072–0x15084`: high byte `0x5344`, low byte `0x5345`, объединяются в 16 бит |
| Два состояния измерения | В состоянии 0 отсчёт сохраняется в RAM `0x792`; включается следующий канал через `0x534b=2`. В состоянии 1 код сравнивает второй отсчёт с первым: сохраняет первый либо отрицание второго |
| Буфер | RAM `0x16f`, 200 signed halfword; индекс RAM `0x7d4` |
| Обработка 200 выборок | `0x114ac`; сумма, минимум и максимум; из суммы вычитаются две крайние выборки, затем деление на 198 |
| Масштаб и калибровка | `0x1152b–0x115ac`: RAM `0x10` / 4096, коэффициент 32.258, отдельные коэффициенты для положительного и отрицательного направления из RAM `0x743` и `0x73f` |
| Ток до фильтра | float RAM `0x737`, пороги и режимные условия могут обнулить значение |
| Фильтр | float RAM `0x73b`; ветка `0x116f0–0x1171e`: `0.3 × новый + 0.7 × старый`; присутствуют ветки прямого присвоения и обнуления |
| Значение для передачи | `0x12534–0x125ce`: читает `0x73b`, преобразует в signed 16-bit RAM `0x4f2` |
| Команда `0x42` | Таблица по `0x8f0b`, диспетчер `0x179eb`, ветка `0x9b28`; вызывает форматтер `0xe5a6` |
| Поле тока | Форматтер читает структуру RAM `0x49b` + `0x57` = `0x4f2`, сначала старший байт, затем младший; кодирует ASCII hex |

Для 30 ячеек и 8 температур (инициализация количества температур: `0x15182`) информационная часть имеет 93 байта. Ток находится в байтах **80–81**, big-endian. Это совпадает с полем, которое парсер основной платы 2.41 принимает и передаёт в F1/page0. Так соединены производитель поля внутри BMS и ранее исследованный потребитель в основной плате.

Численная обработка до порогов, для средней выборки `M` после удаления крайних и значения `R=RAM[0x10]`:

```text
B = M * R / 4096 * 32.258
положительное направление: I = B * (1.79700005 / 3.54999995) * RAM_float[0x743]
отрицательное направление: I = B * 0.5 * RAM_float[0x73f]
```

Это описание конкретного блока, не полная модель всех режимов. Форматирование перед передачей делит float на 10 с усечением; при `0 < |I| < 5000` предварительно прибавляет `+50` либо `-50`. Вблизи нуля работают отдельные проверки. Единицы физического тока, источник и обновление `R`, аппаратные номиналы, реальные коэффициенты калибровки и точность требуют дальнейшего разбора. Числа ниже — управляемые входы офлайн-проверки, не измерения на колесе.

## Проверка исполнением

При `R=3300`, двух коэффициентах 1.0 и RAM `0x815=4` (допускает отрицательное направление в исследованной ветке):

| Знаковый отсчёт | Float RAM `0x737` и `0x73b` | Signed поле | Байты ответа 80–81 |
|---:|---:|---:|---|
| 0 | 0 | 0 | `00 00` |
| +100 | 1315.56165 | 136 | `00 88` |
| −100 | −1299.45557 | −134 | `ff 7a` |
| +1000 | 13155.61523 | 1315 | `05 23` |
| −1000 | −12994.55566 | −1299 | `fa ed` |

Всего семь случаев проходят всю цепь: 400 чтений управляемых ADC-регистров → 200 выборок → обработка → форматирование → полезная нагрузка `0x42`. Отдельно проверены отбрасывание крайних выборок и фильтр (новый=1000, старый=500 → 650). Код прошивки не изменён, её помощники не заменены заглушками. Периферия представляет инертную память: это проверка потока данных и инструкций, не симуляция электроники, частоты выборок или полного колеса.

Используется `naken_asm` commit `247c23706909f09bac77c587780b8a826bbda27c`. В симуляторе исправлена обнаруженная ошибка расчёта signed-overflow V для 8/16 бит: первоначальная реализация неверно исполняла сравнение `−9999 < 0`. Точный патч сохранён в `patch_naken.py`; также убрана печать баннера на каждом шаге. Изменения относятся к инструменту, не прошивке. `executed-current-path.asm` содержит только реально исполненные начала инструкций: inline-константы float не ошибочно представлены как код.

```sh
# При необходимости заново получить исходный дамп и извлечь образ:
python research/s22-bms-current/bms210/extract_image.py
# Или использовать уже скачанный capture.bin:
python research/s22-bms-current/bms210/extract_image.py --capture /path/to/capture.bin

git clone https://github.com/mikeakohn/naken_asm /tmp/naken_asm
git -C /tmp/naken_asm checkout 247c23706909f09bac77c587780b8a826bbda27c
bash research/s22-bms-current/bms210/build_simulator.sh /tmp/naken_asm
python research/s22-bms-current/bms210/trace_bms210.py
```

Выходы: `image_manifest.json`, `evidence.json`, `executed-current-path.asm`. Для разбора не выполняется запись в колесо или изменение настроек реальной BMS.

## Каталог KingSong: проверенная граница

У BMS действительно своё имя модели и свой формат серийного идентификатора. Проверены `KSS22BA`, `KSS22BA-2202`, `KSS22BA-2202-2.10`, `KS-S22BA` через публичный `firmware/getVersionInfo`; ответ — пустой список. Это не доказывает отсутствия прошивок: выбор нужных параметров BMS-каталога остаётся открытым.

В официальном SoftTuner 1.4.163 есть `swap/getBMSList` и поля `bms_firmware_name`, `bms_firmware_version`, `bms_firmware_type`, `bmsName`, `bmsTypeNum`; маршрут отвечает требованием авторизации. Поэтому полученный здесь образ честно обозначен как извлечённый из публичного дампа. Он не выдан за загрузку из официального каталога. Проблема каталога больше не блокирует первый практический ответ.

Вывод ограничен найденной BMS 2.10 семейства `KSS22BA-2202`; перенос на другие ревизии BMS и новые версии требует сравнения образов. Тип физического датчика (шунт или Hall) пока не доказан.
