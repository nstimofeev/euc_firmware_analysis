# S22: источник батарейного тока — первый срез 2026-10-11

## Ответ и граница результата

**Ток батареи в найденной прошивке BMS `KSS22BA-2202-2.10` получен измерением через собственный ADC.** Прослежена и исполнена цепь ADC → 200 выборок → масштаб/калибровка → фильтр → байты 80–81 ответа `0x42`. Отдельный STM8-образ извлечён из публичного дампа основной платы; CRC совпала с заголовком подготовленного обновления. Подробности, оригинальный образ, адреса и воспроизведение: [BMS 2.10](bms210/REPORT_RU.md).

**Батарейный ток основной платы (`BusCurrent`, затем `TotalCurrent`) в проверенной версии 2.41 также получен измерением через ADC.** Основная плата имеет свой измерительный тракт, а для страницы отдельной батареи принимает готовое значение из ответа BMS. Ниже сохранён разбор принимающей стороны и основного ADC.

Тип физического датчика BMS, его номиналы и распространение результата на другие аппаратные ревизии пока не установлены. Прямое получение BMS из официального каталога остаётся открытым; это не препятствует анализу найденного образа.

## 1. Измерительный тракт основной платы 2.41

Проверено по исходному бинарнику SHA-256 `99491754f5478caf5d97a5fa31c0a17bc7be55f0c14ee3f87058b55916fe9509` и восстановленной начальной RAM SHA-256 `aaa8b3bc063cf1c0f7e200d01b6c1c204161abd764ad9b7dbce6048866a7ffea`.

| Звено | Доказательство |
|---|---|
| ADC → RAM | `0x0800c8e0` настраивает DMA: источник `0x4001244c`, приёмник `0x200034f0`, 9 halfword, CCR=`0x5a1`. Исполнены оригинальные инструкции настройки; MMIO — инертная память. |
| Нужный отсчёт | `0x0800d978` читает halfword `0x200034f4`, третий элемент DMA-буфера; `>>4` соответствует объявленному в настройке ADC левому выравниванию. В настройке последовательности `0x0800c40c–0x0800c418` ранг 3 получает канал 0. |
| Нулевое смещение | `0x0800c6b0` накапливает две группы по 64 отсчёта и делит сумму на 128; ноль хранится в `0x2000037c`. В офлайн-проверке 128 постоянных отсчётов 2048 дают ноль 2048. |
| Масштаб и первый фильтр | Блок `0x0800d978–0x0800d9a8` обновляет `0x20000324` по формуле ниже. |
| `BusCurrent` | Блок `0x08020ba8–0x08020bbe` обновляет `0x200032c4`; имя `BusCurrent` подтверждено диагностическим дескриптором `0x080278fc`. |
| `TotalCurrent` | `aggregate_telemetry`, `0x08023e60`, копирует `BusCurrent` в `0x200030cc` при `0x200030f4 > 150`. Имя `TotalCurrent` — дескриптор `0x0802798c`. Это условная ветка, не утверждение обо всех режимах зарядки/запуска. |

Регистры ADC/DMA названы по карте STM32F1-совместимой периферии, как в существующем анализе; это не отдельная идентификация марки MCU. Первичный справочник: [ST RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f103xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf), ADC regular sequence/data alignment и DMA channel registers.

С целочисленным делением с усечением к нулю:

```text
A = uint16(RAM[0x200034f4]) >> 4
Z = int16(RAM[0x2000037c])
C_new = trunc((trunc((A-Z)*38/10) + 49*C_old) / 50)
BusCurrent_new = trunc((9*BusCurrent_old + C_new) / 10)
```

То есть вычисления здесь являются обработкой измеренного сигнала. Физический датчик (шунт/усилитель/Hall), его номиналы, реальная точность, калибровка в амперах и частота вызовов этой цепи данным срезом не установлены. Разбор версии 2.41 не доказывает автоматически ту же реализацию на всех ревизиях платы или во всех ранних версиях.

## 2. Ток в ответе BMS

Общий парсер 2.41: `0x08013d1c`. В исследованной ветке ожидаемой команды `0x42` принимаются информационные части длиной 93 либо 104 декодированных байта. Нумерация ниже начинается с нуля внутри полезной нагрузки.

| Поле | Вход | RAM блока 0 | RAM блока 1 | Выход к приложению |
|---|---|---|---|---|
| Ток BMS | байты 80–81, big-endian u16 | `0x200050c6` | `0x200053ce` | `F1`, страница 0, байты 4–5 little-endian (блок 0 проверен исполнением) |
| Напряжение BMS | байты 82–83, big-endian u16 | `0x200050c8` | `0x200053d0` | `F1`, страница 0, байты 2–3 little-endian |

Вызов кодека для поля тока читает ASCII от смещения `0xad` полного кадра: `13 + 2*80`. Размер структуры батареи — `0x308`, её база — `0x20004e24` для блока 0. Поле тока имеет смещение `0x2a2` внутри структуры.

Исполнены оригинальные валидатор ASCII/контрольной суммы, кодеки и парсер без заглушек для 20 комбинаций: два блока × две допустимые длины × пять значений (`0`, `1000`, `0xffff`, `0x8000`, `0xfc18`). В каждом случае принятые 16 бит равны входным; второй блок не изменяется; независимый `BusCurrent=4321` сохраняется. Это доказывает происхождение поля на **принимающей стороне**; производитель внутри BMS отдельно подтверждён новым срезом 2.10.

Для блока 0 дополнительно исполнены `0x080178e8` и исходный упаковщик `0x0800f88c`: во всех 10 случаях F1/page0 передаёт те же 16 бит без перерасчёта. Например `1000` превращается в `e8 03` в байтах 4–5; `0xfc18` в `18 fc`. Число не складывается с током другой батареи и не заменяется `BusCurrent` в этой ветке. Новый срез BMS 2.10 подтверждает signed 16-bit поле; физические единицы и аппаратный датчик требуют дальнейшей проверки; u16 в парсере описывает сохранение битов, а не утверждение о беззнаковом физическом токе.

## 3. Получение прошивки самой BMS

Первоначальные попытки официального каталога записаны в `acquisition.json`. После них найден и проверен отдельный образ BMS 2.10 в публичном дампе S22. Его происхождение, SHA-256, CRC, своё имя модели, адресное размещение и статус официального каталога описаны в [новом срезе](bms210/REPORT_RU.md). `bms210/image_manifest.json` фиксирует неизменяемую ссылку на исходный дамп.

## Воспроизведение

Из корня репозитория с зависимостями `requirements.txt`:

```sh
python research/s22-bms-current/trace_current.py
```

Результат — `evidence.json`. Проверка исполняет оригинальные инструкции основной платы: настройку DMA, калибровку нуля, блоки обработки тока, парсер BMS и упаковку F1. Ни одной заглушки помощника; MMIO инертно, настоящие ADC/DMA/BMS/UART не моделируются. Формула на Python используется для сравнения результатов исполнения, а не называется эмуляцией прошивки. Воспроизводится первый срез, не работа всего колеса или всего MCU BMS.
