## Доступность бинарных данных

Репозиторий содержит оригинальные и расшифрованные прошивки S22 и восстановленную начальную RAM вместе с отчётами, скриптами и экспортом Ghidra. Полная публикация материалов явно разрешена владельцем 2026-09-29. Восстановленные RAM-файлы получены из приложений эмуляцией распаковки; это не дампы работающего колеса.

`FIRMWARE_SHA256SUMS.txt` проверяет бинарные данные; `SHA256SUMS.txt` — остальные материалы. После клонирования отдельное скачивание архива для проверок S22 не требуется.

## Повторение проверок

Из корня репозитория:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python s22-code-audit/run_checks.py
.venv/bin/python ks16x/verify_offline.py
```

Проверки выполняют только локальное чтение файлов и эмуляцию оригинального машинного кода. Они не подключаются к колесу и не используют сеть. Установка зависимостей требует доступа к пакетам.

## Состав

- `s22-developer-pack/firmware/original/`: 15 исходных зашифрованных файлов.
- `s22-developer-pack/firmware/decrypted/`: 15 расшифрованных файлов; это неизменённые приложения, не исходный C-проект.
- `s22-developer-pack/diagnostics/`: извлечённые именованные записи с адресами и сырыми метаданными.
- `s22-developer-pack/HISTORY_RU.md`, `release_history.json`, `evidence/`: сохранённая история производителя и ссылки/хеши.
- `s22-platform-research/`: начальная RAM и воспроизводящий её распаковщик.
- `ks16x/`: официальный каталог KS-16X, три оригинала/расшифровки, начальные данные RAM и автономные проверки.
- `ks16x-platform/`: аппаратные наблюдения с первичными источниками; без назначения прошивок платам.
- `s22-code-audit/`: новые скрипты, JSON результатов, адресованный дизассемблер.
- `s22-code-audit/function_diff.py`: воспроизводимый эвристический поиск кандидатов между двумя версиями, например `python s22-code-audit/function_diff.py 227 229`. Создаёт локальные JSON/diff; совпадение нормализованных инструкций не доказывает одинакового поведения.
- `decompiled/`: автоматический C-псевдокод, листинги и граф прямых вызовов всех 15 образов.
- `ghidra/`: воспроизводимый импорт и экспорт Ghidra.
- `research/`: адресованные участки, результаты новых эмуляций и журналы Ghidra.
- `SHA256SUMS.txt`: контрольные суммы файлов пакета, кроме самого списка.

Пример просмотра:

```sh
.venv/bin/python s22-code-audit/inspect_s22.py 235 dis 0x080156d0 0x17c
```

Никаких модифицированных образов или готовых патчей для установки пакет не содержит. Совместимость всех выпусков со всеми платами и моторами не установлена. Принятие модифицированного приложения загрузчиком S22 также не проверено.

## Первый срез анализа тока BMS — 2026-10-11

- [Источник тока: ADC основной платы и поле ответа BMS](research/s22-bms-current/REPORT_RU.md).
- Проверка: `python research/s22-bms-current/trace_current.py`.
- `BusCurrent` 2.41 имеет измерительный источник. Отдельный ток батареи передаётся из BMS без перерасчёта; в BMS 2.10 источник также подтверждён как собственный ADC.


BMS S22 2.10 (`KSS22BA-2202`): [собственный ADC → поле тока ответа 0x42, образ и воспроизводимая проверка](research/s22-bms-current/bms210/REPORT_RU.md).

S22 2.41: [измерение фазных токов ADC2, пары каналов по секторам и путь в Iq/Id](research/s22-phase-current/REPORT_RU.md).

S22 2.41: [размер приложения, разметка flash/RAM и границы свободного места](research/s22-memory/REPORT_RU.md). Проверка: `python research/s22-memory/inspect_memory.py`. Номинальная ёмкость конкретного MCU остаётся неподтверждённой.

S22 2.41: [что хранится во flash и где риск изменений](research/s22-flash-map/REPORT_RU.md). Оригинальным кодом проверены две копии настроек, EEPROM/IMU-калибровка, калибровка напряжения в загрузочной области, BMS-запись за 64-КиБ erase-loop и внешний SPI logger с chip erase. Исторический OTA стирает непрерывно по размеру без защиты BMS/настроек. 36 сценариев: `python research/s22-flash-map/trace_flash.py`. Подтверждённого большого свободного резерва пока нет.

Загрузчик S22: [публичный SWD-фрагмент 20220406 и происхождение](research/s22-bootloader/REPORT_RU.md), [приём/AES/запись/запуск и восстановление после неудачной прошивки](research/s22-bootloader/RECOVERY_RU.md). Проверки: `python research/s22-bootloader/inspect_bootloader.py` и `python research/s22-bootloader/trace_recovery.py`. Исследованный механизм — повторная передача приложения, без резервного рабочего слота; найдены окно до маркера и пропуск RX-init при повреждении без маркера. Основной поток проверен офлайн; совпадение с загрузчиком конкретного колеса и работа восстановления через BLE не установлены.

S22 на Fedora: [план записи реального обновления с Android, прямого BLE-клиента, стенда и шлюза](research/s22-live-capture/PLAN_RU.md). Добавлены автономная проверка Android btsnoop/bugreport и список 95 диагностических записей ветки чтения 2.41; 20 записей ветки записи исключены. Реальное подключение и доступ к расширенной диагностике через BLE пока не проверены. Проверки: `python3 research/s22-live-capture/test_capture.py` и `python3 research/s22-live-capture/catalog.py`.
