# Память основной платы S22: образ 2.41 и свободное место

Проверено 2026-10-11. КиБ = 1024 байта. Это разбор основной платы; память MCU каждой BMS сюда не суммируется.

## Короткий ответ

- Основное приложение 2.41: **132 992 байта = 129,875 КиБ**. Оригинальный зашифрованный файл в репозитории имеет тот же размер; расшифровка не увеличивает образ.
- Перед фиксированным размещением обновления BMS остаётся **2176 байт = 2,125 КиБ** непрерывного адресного пространства. Это геометрический зазор, а не доказательство принятия увеличенного образа загрузчиком.
- Приложение резервирует **32 624 байта = 31,859375 КиБ RAM**, включая **2 КиБ heap** и **3 КиБ основного стека**. Фактический остаток кучи/стека во время езды неизвестен.
- В опубликованном SWD-файле имеется 512 КиБ адресного пространства, верхние 256 КиБ заполнены FF. **Это не доказывает номинальную ёмкость конкретного MCU.** Точную маркировку RC/RE пока не удалось подтвердить.
- Есть внешняя SPI flash **8 МиБ** по первичному исследованию владельца платы. Прошивка обращается к ней для записей. Её живой дамп отсутствует: количество свободных байтов неизвестно.

## Разметка внутренней flash

Границы справа исключающие. Разметка нижних 256 КиБ подтверждается оригинальными инструкциями 2.41 и старым публичным дампом. Нельзя считать все FF внутри резервов свободными.

| Диапазон | Размер | Назначение / статус |
|---|---:|---|
| `08000000–08008000` | 32 КиБ | Область перед приложением, загрузчик/служебный код в старом дампе; не 32 КиБ сплошного кода |
| `08008000–08028780` | 129,875 КиБ | Файл приложения 2.41, включая данные и метаданные |
| `08028780–08029000` | 2,125 КиБ | Зазор до BMS; одна целая страница 2 КиБ и 128 байт хвоста предыдущей |
| `08029000–08039000` | 64 КиБ | Область стирания BMS: функция `08017344`, ровно 32 страницы по 2048 байт |
| `08039000–0803a000` | 4 КиБ | Продолжение адресного диапазона записи BMS: принятый заголовок допускает до 5800 записей и конец `08039fe8`, хотя erase-loop ограничен `08039000` |
| `0803a000–08040000` | 24 КиБ | Служебные страницы: счётчики, конфигурация, маркеры, журнальные записи; не свободная область |
| `08040000–08080000` | 256 КиБ | В старом SWD-файле FF; наличие физической памяти и возможность использования требуют отдельной проверки |

Начало приложения подтверждено вектором reset `0800820d` и адресами кода. Размер получен из файла, SHA-256 в evidence.json. BMS erase-loop исполнен в Unicorn, низкоуровневые flash-функции заменены записью вызовов; это проверка адресов, не эмуляция контроллера flash.

Восстановленный ранее staged BMS 2.10 содержит 5115 записей по 12 байт: **61 380 байт**, плюс 8 байт заголовка. Это транспортный образ для обновления BMS, а не размер flash её MCU. С ним в 64-КиБ области остаётся 4148 байт, но слот нельзя занять своим кодом: штатное обновление BMS его сотрёт.

Уточнение следующего среза: [полная карта постоянных данных и риска изменений](../s22-flash-map/REPORT_RU.md). Оригинальный код подтвердил использование бывшего 4-КиБ «промежутка» BMS-writer и отсутствие проверки конца последнего пакета по объявленному числу записей. В синтетическом офлайн-прогоне последний пакет достиг `0803a18c`; это отдельный протокольный риск, не наблюдение порчи штатным обновлением. Найдены также калибровочные поля внутри загрузочной области `08001340/1342/1344`, подробные форматы настроек и внешние кольцевые журналы.

## RAM: резерв, а не измеренная загрузка

Scatter-таблица по `08028418`: `.data` 2548 байт по `20000000`; обнуление 30076 байт от `200009f4` до `20007f70`. Последний резерв включает heap и основной стек, поэтому их нельзя прибавлять повторно.

Оригинальная функция `08008228` возвращает R0=`20006b70`, R1=`20007f70`, R2=R3=`20007370`. По соглашению ARM runtime это heap base, stack base, heap limit, stack limit. Получается heap `20006b70–20007370` (2048 байт), основной стек `20007370–20007f70` (3072 байта). Исходный SP из вектора равен `20007f70`. Остальные резервы до heap: 27504 байта. Стеки задач могут лежать внутри этих областей; отдельный main stack не равен суммарной памяти всех задач.

В первых 32 КиБ над начальным SP остаются 144 байта, но они не отражают живую доступную память. Верхняя RAM не используется scatter-таблицей: потенциальный резерв зависит от реального чипа и использования загрузчиком.

По официальной таблице GD32F303: **RCT6 — 256 КиБ flash / 48 КиБ SRAM; RET6 — 512 КиБ flash / 64 КиБ SRAM**. Для RE flash разделена на 256 КиБ code area + 256 КиБ data area; дополнительную половину нельзя без проверки называть готовым продолжением быстрого приложения. При RC сверх текущего резерва RAM номинально 16528 байт, при RE — 32912 байт. Это условные арифметические остатки, не доказательство доступности конкретной платы.

## Внешняя память и источники

Автор SWD-исследования сообщает 8 MB flash на SPI2 и прикладывает datasheet W25Q64JV (64 Mbit = 8 МиБ). Псевдокод 2.41, например `0801a4d0` и вызовы `080154e0/08015660`, показывает записи/чтения по адресам до `600000`, кольца 64-байтовых записей. Полная семантика и занятость внешних областей здесь не восстановлены. Эта память не входит в размер основного приложения.

- [Первичный SWD-проект, фиксированный commit](https://github.com/jeremy-prater/ks-s22-mods/tree/9258eac039304991a815b8880c4dddca7a4e983c), `firmware/capture.bin`, SHA-256 `e1ad38200189fd445cf9cf805206ed853398124b2ffa2f5326040269d7fc3552`.
- [Официальный GD32F303xx Datasheet Rev3.0](https://www.gd32mcu.com/data/documents/datasheet/GD32F303xx_Datasheet_Rev3.0.pdf), таблица 2-1, раздел 3.2; проверен 2026-10-11.
- Размеры оригинального и расшифрованного файла 2.41 сверены с GitHub tree `403a0a02248c1468886679016be208602ad6cb8e`.

## Воспроизведение и открытые вопросы

Из корня репозитория: `python research/s22-memory/inspect_memory.py`. Зависимости из requirements.txt. Дополнительно `--capture /path/to/capture.bin` проверяет хеш и верхнюю половину старого публичного дампа; путь пользователя не сохраняется в evidence.

Следующий конкретный шаг — прочесть маркировку MCU или аппаратный регистр ёмкости flash на известной ревизии платы; затем проверить загрузчик на ограничения размера обновления. Для RAM нужен runtime high-water mark стека/heap; по файлу его получить нельзя. Выводы здесь не переносятся автоматически на S22 Pro и другие ревизии.
