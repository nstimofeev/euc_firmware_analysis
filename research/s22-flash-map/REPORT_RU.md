# S22: содержимое flash и границы риска

Проверено 2026-10-11 для **приложения 2.41**. Загрузочная область — исторический SWD-дамп другого S22 с датой `20220406`, а не дамп колеса пользователя. Адреса справа исключающие; КиБ = 1024 байта. Здесь исследуется память **основной платы**: staging BMS в её flash не является памятью MCU батарейной платы.

**Вывод:** нижние 256 КиБ почти полностью распределены между приложением, загрузчиками, обновлением BMS и постоянными данными. Свободные FF-байты в служебных страницах не являются независимыми резервами. Единственный целый геометрический зазор перед BMS — страница `08028800–08029000` на 2 КиБ. Исторический загрузчик допускает заголовок увеличенного до этой границы образа и не стирает BMS; запуск такого приложения и соответствие загрузчика текущему колесу ещё не доказаны. Большой потенциальный резерв — верхняя внутренняя flash, если она физически существует на конкретном MCU, либо внешняя SPI flash после изменения правил её стирания.

## Внутренняя flash

| Диапазон | Размер | Содержимое и риск |
|---|---:|---|
| `08000000–08004000` | 16 КиБ | Основной загрузчик, векторы, метаданные. Внутри есть **заводская калибровка напряжения** `08001340/1342/1344`. Максимальный риск: повреждение может лишить штатного восстановления или исказить измерение. |
| `08004000–08008000` | 16 КиБ | Второй загрузочный образ и его данные; пишет собственную привязку в `08005300/5304`. Это не запасная копия приложения. |
| `08008000–08028780` | 129,875 КиБ | Приложение 2.41: векторы, код управления мотором, константы, таблицы, начальная RAM, диагностика, заголовок допуска/привязки. Два поля самого приложения тоже изменяются штатно: `08008300/8304`. |
| `08028780–08028800` | 128 байт | Хвост последней занятой страницы приложения. Стереть отдельно нельзя. |
| `08028800–08029000` | 2 КиБ | Целая страница между концом файла и staging BMS. Кандидат для дальнейшей проверки, **не подтверждённое безопасное место**. |
| `08029000–08039000` | 64 КиБ | Штатное стирание staging BMS: 32 страницы по 2 КиБ. Заголовок на `29000/29004`, записи с `29008`. Любые наши данные здесь пропадут при обновлении BMS. |
| `08039000–0803a000` | 4 КиБ | **Продолжение адресного диапазона записи BMS**, а не свободный промежуток. Допустимый заголовком размер выходит за 64-КиБ erase-loop. |
| `0803a000–0803a800` | 2 КиБ | Журнал накопительного счётчика: halfword-записи, при заполнении перенос итога в конфигурацию. По потребителю `20003110` это счётчик времени; точные единицы здесь не утверждаются. |
| `0803a800–0803b000` | 2 КиБ | Служебный маркер `28536692`, проверка/запись/сброс приложением. Полный смысл всех веток пока не восстановлен. |
| `0803b000–0803c000` | 4 КиБ | Две страницы журнала «ключ → значение», включая **калибровку инерциальных датчиков**. Это программная EEPROM на flash. |
| `0803c000–0803d000` | 4 КиБ | Два слота постоянной конфигурации, каждый в своей 2-КиБ странице. В каждом 264 байта данных и 8 байт контрольной суммы. Параметры регулятора, серийная строка, настройки, поправка напряжения и накопительные данные. |
| `0803d000–0803d800` | 2 КиБ | Маркер основного OTA `55aaaa55`, участвующий в выборе загрузочного сценария. Изменение может переключить поведение при включении. |
| `0803d800–0803e000` | 2 КиБ | Маркер второго загрузочного образа `28635690`. Та же категория риска. |
| `0803e000–08040000` | 8 КиБ | Два дублирующих журнала одной 20-байтовой записи: каждая копия использует пару 2-КиБ страниц. Накопленный пробег, энергия, дополнительные поля и CRC. Это не резервные прошивки. |
| `08040000–08080000` | 256 КиБ | FF в историческом публичном файле. Физическая ёмкость текущего MCU и владение областью не установлены. Для GD32F303RE эта половина — data area с отличающимся временем чтения; для RC её нет. |

Образ приложения имеет 132992 байта, SHA-256 `99491754f5478caf5d97a5fa31c0a17bc7be55f0c14ee3f87058b55916fe9509`. Наличие только двух загрузочных образов перед приложением и восстановление OTA исследованы отдельно в [RECOVERY_RU.md](../s22-bootloader/RECOVERY_RU.md). Карта не доказывает соответствие загрузчика текущему колесу.

В исторических первых 32 КиБ есть ещё **четыре целиком FF-страницы**, суммарно 8 КиБ: `08003800–08004000` и `08006800–08008000`. Они не названы свободными: это промежутки внутри области загрузчиков конкретного старого дампа, отсутствие их резервирования не установлено. Обычный исследованный OTA приложения начинается с `08008000` и свой код в эти промежутки не устанавливает. Использование их потребовало бы отдельного способа записи и проверки текущего загрузчика/защиты; по риску это отличается от добавления страницы в конец приложения.

## Почему 4 КиБ после 64-КиБ staging нельзя занимать

Оригинальный обработчик `080164bc` принимает объявленное число записей `< 0x16a9`, то есть до **5800**. `08017344` стирает только `08029000–08039000`. `0801739c` пишет три слова записи по формуле:

`address = 08029008 + (start_index + record_index) * 12 + word_index * 4`.

Последняя запись при числе 5800 начинается в `08039fdc`; конец записи — **`08039fe8`**. Уже запись с индексом 5460 пересекает `08039000`. Это подтверждено исполнением оригинальных инструкций, а не только C. Две следующие страницы этот erase-helper не стирает: при нестертом содержимом реальные записи могут завершиться ошибкой. Отдельно доказана попытка адресованной записи; её успех на железе не заявляется.

Есть дополнительная граница риска: у команды `0x7a/0x31` проверяется `cursor < total`, равенство индекса и `chunk_count < 37`, но **не `cursor + chunk_count <= total`**. Синтетический пакет с корректными CRC, total=5800, cursor=5799 и count=36 передан оригинальному обработчику. Он вызвал 108 word-program операций вплоть до конца **`0803a18c`**, то есть зашёл в страницу счётчика `0803a000`. Это не наблюдение ошибки официального клиента и не доказательство порчи конкретного колеса. Это доказательство, что граница staging сама по себе не защищает соседнюю страницу от некорректного размера последнего пакета.

## Настройки и калибровки

### Два слота конфигурации

Указатели `08027070` содержат `0803c000`, `0803c800`. `08021934` суммирует **66 uint32** с переносом в 64 бита и сравнивает два следующих слова. `0802199c` предпочитает валидный слот 0, иначе слот 1. `080219cc` загружает 264 байта в RAM `20003198–200032a0`. Если оба слота не проходят сумму, `080219f8` ещё пытается спасти **20 байт серийной строки** по смещению `0x62`, если она начинается с `KS`; это не восстановление остальных настроек. `080225b8` применяет значения по умолчанию при неверной конфигурации/схеме.

`08021b08` стирает целую страницу и пишет 68 слов, итого **272 байта**. Оставшиеся **1776 байт страницы** не свободны для независимого хранения: следующий save их уничтожит. `08021a90` выбирает порядок обновления двух копий с проверкой результата. Проверены выбор резервной копии, порядок стирания при двух валидных слотах и 68 границ отказа word-program при создании новой копии рядом с валидной старой. Старый слот сохранялся во всех этих неполных записях. Это ограниченная модель ошибок, не тест brownout внутри операции или гарантия аппаратной атомарности.

Некоторые важные поля по смещениям от `20003198` после загрузки:

| Смещение | Что установлено |
|---|---|
| `+0x1e` и следующие поля | Профиль регулятора, потребители `08024990/08022800`; их изменения способны менять управление мотором. |
| `+0x58/+0x5a` | Поправка напряжения и её инверсия; загрузка `080225b8`, измерительный потребитель `0800d930`. Точные физические единицы поправки здесь не устанавливаются. |
| `+0x5e/+0x60` | Основа накопительного счётчика, к которой добавляется журнал `0803a000`. |
| `+0x62`, 20 байт | Серийная строка; она влияет и на ветки конфигурации/уставки тока, а не только на имя Bluetooth. См. [исследование конфигурации](../s22-configuration/REPORT_RU.md). |
| `+0x104` | Маркер схемы `20220430`, проверяемый при запуске. |

Не все поля названы; менять структуру целиком или пересаживать её с другого колеса нельзя считать безопасным действием только потому, что пересчитана сумма.

### Журнал ключей и калибровка IMU

Страницы `0803b000/0803b800`: halfword заголовка `ffff` означает erased, `0000` — active, `eeee` — перенос. Запись имеет **4 байта: значение uint16, затем ключ uint16**, начинается после 4-байтового заголовка. Таблица известных ключей находится в исходной RAM `200000a6`, число ключей 70. `0800b17c` ищет последнее значение; `0800b458` добавляет запись и при заполнении вызывает перенос `0800af54`. Инициализация/восстановление — `08015818` и `0800c268`.

`08022c3c` сохраняет группу калибровочных значений и маркер `0729` через `08022b18`, добавляющий CRC. `08020a04` читает/проверяет и загружает RAM `200033f8…20003410`. Потребитель `0800fdec` вычитает эти поправки из измерений ускорения и гироскопа. Прогон оригинального кода подтвердил полную запись → CRC-проверку → восстановление семи значений. Поэтому стирание «EEPROM» может убрать калибровку датчиков, используемых балансировкой.

### Калибровка напряжения внутри загрузочной области

В историческом дампе: `08001340=c0ef`, `08001342=053d` (1341), `08001344=3f10`. Приложение `08015fbc` проверяет теги и диапазон коэффициента, затем загружает его в `200002ec`. `08023444` при выполнении условий записывает коэффициент в `08001342` и тег завершения в `08001344`; это путь однократного программирования стертых halfword без стирания страницы.

Оригинальное чтение исторического коэффициента и запись в синтетически очищенные поля исполнены. Страница стирания **`08001000–08001800`** содержит также данные загрузочного образа. Поэтому ни «стереть настройки», ни «переписать первые 32 КиБ чужим загрузчиком» не являются точным способом обращения с этой калибровкой.

### Счётчики и маркеры

`08022cc0` добавляет halfword в `0803a000`; при заполнении стирает страницу и переносит итог в конфигурацию. Наблюдаемая арифметика добавления и переноса отличается множителем 10; физические единицы нельзя назначать по названию поля. `08020a88` восстанавливает итог при старте. RAM `20003110` увеличивается раз в 50 вызовов `0800a2a4` и используется в вычислении средней скорости: трактовка как времени поддержана потоком данных, перевод в секунды здесь не проверяется.

`0800f664` вычисляет CRC записи RAM `2000008c…2000009f` и пишет **одинаковые 20 байт в оба журнала** `0803e000/e800` и `0803f000/f800`. `08022ae4` обновляет накопленный пробег и энергию; потребители `0802136c/08009d6c` связывают поля с диагностикой. Подтверждено оригинальной записью обеих копий. Дублирование и перенос страниц нужны для сохранения записей, а не для свободного использования второй страницы.

Маркеры OTA — данные с исполняемой семантикой. `0801ff7c` стирает страницу `0803d000` и пишет `55aaaa55`; `0801ff5c` её очищает. Исторический загрузчик по ним выбирает сценарий старта/обновления. У приложения есть записи в собственные поля `08008300` (`0801f0bc`) и `08008304` (`0801f8a4→080236a8`). Второй загрузочный образ тоже изменяет собственные поля привязки. Идентификатор MCU по `1ffff7e8…` читается из аппаратной области; это не пользовательский flash-слот для замены серийника.

## Внешняя SPI flash

Владелец исторически исследованной платы указал **W25Q64JV, 8 МиБ**. Емкость конкретной платы пользователя ещё не прочитана. Код 2.41 использует 24-битные адреса и следующие области:

| Адрес SPI | Подтверждённое использование |
|---|---|
| `000000–200000` | Первое кольцо 32768 записей по 64 байта, индекс `&7fff`; основные записи телеметрии/поездки. |
| `200000–210000` | Отдельный 64-КиБ блок для служебной записи первого кольца. Сброс стирает блок `20`; затем пишет 64 байта с первым словом `01451090`. |
| `210000–400000` | Кандидат для дальнейшего анализа: использования обычными кольцевыми записями не найдено. Отсутствие любых других потребителей не доказано. |
| `400000–600000` | Второе кольцо 32768 записей по 64 байта; отдельный источник событийных записей `08019e08`. |
| `600000–610000` | Служебный 64-КиБ блок второго кольца: аналогичное стирание блока `60` и 64-байтовая запись. |
| `610000–800000` | Та же категория кандидата, **не доказанное свободное место**. |

Оригинальный `0801a4d0` исполнен для записей обоих колец, служебных записей и полных сбросов: соответственно блоки `00…20` и `40…60`, 33 блока по 64 КиБ каждый. Драйверы `080154e0/08015660` выдали ожидаемые SPI-байты: `03` Read, `06` Write Enable, `02` Page Program; запись ограничена 64 байтами и концом 256-байтовой программируемой страницы. `080153f0` выдал **`d8` — стирание блока 64 КиБ**.

Важнейшее ограничение сохранности: `08015438` выдал **`c7` — стирание всей микросхемы**, и этот путь подтверждён в оригинальном автомате журнала при состоянии `200065f4=1`. Поэтому даже запись в кандидатные промежутки может быть уничтожена штатной функцией. Доступность этой команды внешнему клиенту и все условия её постановки здесь не установлены. Без живого дампа нельзя посчитать фактически заполненные журналы или назвать количество свободных байтов.

## Что означает «можно трогать flash»

### OTA не сохраняет соседние разделы при слишком большом размере

Исторический `08000844` сравнивает размер из транспортного заголовка с пределом, рассчитанным через аппаратный регистр, затем вызывает `08002868`. Последний стирает **ceil(size/2048) страниц от `08008000` без границы по BMS/конфигурации**. Оригинальный разбор заголовка и весь erase-loop исполнены с контролируемым, неизмеренным значением регистра `0100`:

| Объявленный размер | Конец стирания | Последствие |
|---:|---|---|
| 132992, файл 2.41 | `08028800` | Стирается последняя занятая страница приложения, вместе с 128-байтовым FF-хвостом. |
| 135168, +2176 байт | `08029000` | Занимается ещё одна страница; staging BMS пока не стирается. |
| 135184, +2192 байта | `08029800` | Из-за округления стирается первая страница BMS. |
| 204800 | `0803a000` | Стирается весь 68-КиБ адресный резерв BMS. |
| 229376 | `08040000` | Стираются также все служебные страницы настроек/журналов/маркеров. |
| 262144 | `08048000` | Стирание выходит в условную верхнюю внутреннюю половину. |

Все шесть заголовков дошли до erase-loop. Это **не тест запуска увеличенного приложения** и не измерение допустимой физической ёмкости. Зато отсутствие защитной границы по разметке в исследованном загрузчике установлено прямо: сохранённый загрузчик сам по себе не предотвращает стирание персональных данных неправильным OTA-размером.

| Действие | Оценка по текущим данным |
|---|---|
| Читать дамп для анализа | Не изменяет содержимое; интерфейс чтения и остановка MCU — отдельный аппаратный вопрос. |
| Менять известную пользовательскую настройку штатным save-путём | Наиболее управляемый вариант после определения поля и его ограничений. Профиль мотора, уставки, напряжение и IMU-калибровку к обычным настройкам не приравнивать. |
| Стереть журналы внешней flash | Меньше прямого риска для основного исполняемого кода, но исчезнет история; зависимость запуска/протоколов от состояния журналов требует проверки. |
| Хранить свои данные в FF-хвостах служебных страниц | Неустойчиво: штатная запись стирает целую страницу/блок. |
| Патчить приложение в прежних границах | Адресная разметка позволяет исследование; корректность исполнения, тайминги, заголовок допуска и восстановление должны проверяться отдельно. OTA переписывает приложение на месте, резервного приложения не обнаружено в исследованном сценарии. |
| Увеличить приложение на 2176 байт | Геометрия и приём заголовка/граница стирания подтверждены для исторического загрузчика. На последней странице 128 байт зазора, на следующей — 2048. Исполнение нового образа, остальная политика допуска и загрузчик конкретного колеса ещё требуют проверки. |
| Занять staging BMS или служебные страницы | Конфликт с действующей прошивкой, калибровкой, обновлением или восстановлением. |
| Изменить загрузчики, векторы, маркеры OTA, привязку | Наибольший риск утраты штатного запуска/восстановления; историческая эмуляция не заменяет известный аппаратный путь восстановления конкретной платы. |
| Использовать верхнюю внутреннюю половину | Сначала подтверждение физической ёмкости, геометрии/драйвера и обращения загрузчика; для кода управления дополнительно время чтения data area. |
| Менять option bytes/защиту | Отдельная аппаратная область, не часть карты свободных байтов приложения; её содержимого текущего MCU нет. В эту работу изменение защиты не входит. |

Основная гранулярность штатного внутреннего стирания — **2 КиБ**, запись — halfword/word. Нельзя заменить произвольные старые значения простым повторным program: по GD32F30x Manual §2.3.6 обычная word/halfword-запись требует стертый адрес, исключение — программирование нуля. Поэтому правка маленького поля может потребовать сохранения и восстановления соседних данных целой страницы. Стандартная библиотека FMC ждёт завершения операций, некоторые журнальные обёртки отключают прерывания (`0800824c/8254`). Эмуляция не проверяет аппаратные задержки: запись/стирание при активном управлении мотором нельзя считать безопасными на её основании.

По GD32F303xx Datasheet Rev3.0, таблица 4-21, ресурс flash указан **100 kcycles**; это предел спецификации при её условиях, а не бесконечное хранилище. Типовое page erase — 45 мс. Это отдельный аргумент против частого сохранения на каждом цикле регулятора. Эти величины относятся к описанному GD32F303, а не автоматически к любой ревизии платы.

## Проверка, источники и открытые вопросы

Воспроизведение: `python research/s22-flash-map/trace_flash.py` из корня, зависимости из `requirements.txt`. **36 сценариев прошли**, включая 68 дополнительных границ отказа записи новой копии. `evidence.json` содержит адреса, значения, статусы и исходящие SPI-байты. `selected-code.asm` содержит оригинальные Thumb-байты и инструкции ключевых функций; `selected-decompilation.c` — только навигационный псевдокод Ghidra. `candidate-functions.json` — статический реестр прямых упоминаний служебных адресов/известных FMC-функций; не доказательство отсутствия косвенных путей. Для исторического OTA повторно используются байты и явные FMC/UART-границы из `research/s22-bootloader/trace_recovery.py`; его `recovery-code.asm` содержит адресованные загрузочные инструкции.

Перехвачены только FMC-границы unlock/flags/erase/program/lock, низкоуровневый SPI byte exchange, IRQ save/restore и очередь ответа. Самих flash/SPI-микросхем, питания, wear, аппаратной блокировки страниц и реального UART/BLE здесь нет. Входные бинарники неизменны; все записи происходят в памяти Unicorn, оборудование не подключалось, OTA-файл не создавался.
